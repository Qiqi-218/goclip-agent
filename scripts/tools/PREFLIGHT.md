# 提交前检查

`preflight.py` 把**三条会直接判定作品无效**的硬约束做成可执行的检查，
免得在最后一天靠人记：

```powershell
E:\huabei\.venv\Scripts\python.exe E:\huabei\tools\preflight.py
```

退出码 `1` 表示有硬约束不合格，可以挂在发布步骤前面当门禁。

## 它检查什么

| 组 | 检查项 | 依据 |
| --- | --- | --- |
| **1 演示视频** | 容器是 MP4 · **时长 ≤ 300 秒** · **体积 ≤ 150MB** | 官方：时长不应超过 5 分钟，不得超过 150MB，文件应为 MP4（不接受其他格式） |
| **2 设计文档** | 四个必填章节（需求分析/设计思路/功能模块/工具平台）都在 · 无未填占位 · 截图 ≥3 张 | 官方：必须提交详细设计文档，包括需求分析、设计思路、功能模块和工具平台介绍；作品简介需 3 幅核心功能截图 |
| **3 密钥** | 受版本控制的文件里没有密钥特征 | 密钥一旦进仓库就会随源码提交 |

## 两个设计取舍

**密钥扫描只扫我们自己的路径。** DSH 上游仓库整棵树里有几十处 `sk-test-…` 之类的
测试夹具，把它们报出来只会训练人忽略报告 —— 那比不报更糟。
所以 `config/` 与 `platform/dsh/packages/video/` 会被扫描；后者是我们加的插件。
形似占位值的匹配会被识别并计数，但不算不合格。

**「未套用官网模板」是警告不是失败。** 模板下载在官网登录后，团队拿到之前这条无法消除；
但它是**会导致文档不合规**的项，所以必须一直显示，不能因为「不是失败」就消失。

## 用法

```powershell
# 默认：视频找 E:\huabei\demo-submit.mp4，文档找 E:\huabei\docs-参赛
python tools/preflight.py

# 指定别的位置
python tools/preflight.py --video D:\submission\demo.mp4 --docs D:\submission\docs

# 只查文档，不查仓库
python tools/preflight.py --no-repos
```
