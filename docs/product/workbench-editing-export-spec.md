# goclip 对话式剪辑工作台：编辑、预览与导出闭环 Spec

版本：1.0 · 日期：2026-10-05 · 状态：待实施方案

本文基于当前工作区源码制定；描述的目标能力不代表已经实现。本次交付是产品与技术规格文档，不包含业务代码实施或服务发布。

## 1. 产品决策

将 goclip 定位为「AI 帮你形成初剪，工作台让你直接修改并交付成片」的轻量视频编辑工具。

用户可以完全通过对话生成成片，也可以在任何阶段进入工作台核对、微调、导出。工作台不是强制流程，也不是工具调用日志的可视化外壳。

核心规则：

1. 用户手动点击剪切、删除、变速，已经表达执行意图，应直接保存并更新预览，可撤销。
2. AI 面对明确、可定位的编辑指令可以执行；面对模糊目标或自主选择内容，先提供可预览方案，用户一次接受后应用。
3. 编辑保存、视频预览、成片导出是三个不同状态，界面必须说清楚。
4. 导出对象是当前时间线的确定版本；导出期间继续编辑不能改变正在生成的文件。
5. 左侧导航、会话、工作台保持三栏；工作台按需要打开，可关闭、拉宽和进入专注模式。
6. 每个可点击操作都必须接通实际业务；不可用功能明确禁用并说明原因。

主闭环：选择素材 → 创建/选择时间线 → AI 初剪或手动编辑 → 预览成片 → 导出 → 下载。

首个正式版本必须交付完整闭环。单独完成新布局、待确认提示或导出按钮，均不满足上线要求。

## 2. 目标用户、场景与设计约束

### 2.1 用户与成功标准

主要用户是处理本地视频的中文创作者：旅行集锦、访谈摘要、录屏片段、短视频提炼。使用场景是普通室内光线下的桌面浏览器，用户一边描述目标一边观看素材、调整节奏。

延续现有主题与语义颜色，不强制切换成专业软件式暗色全屏。播放器使用适合观察视频的中性背景；导航、按钮、状态跟随系统主题。

成功标准：用户无需认识工具名、项目 ID 或 JSON，即可独立完成一次编辑与下载；删除后播放确实跳过该片段；变速影响预览及导出；刷新后编辑仍存在。

### 2.2 已确认约束

- 保留 DSH/Cordis、React、现有 SQLite、OSS、FFmpeg 和视频工具体系。
- 保留 `@xzdarcy/react-timeline-editor` 作为时间线交互层。
- 左侧导航与中间会话常驻；旧详情栏不再作为产品界面出现。
- 不在首次进入页面时自动弹出工作台；由模型显式打开或用户点击打开。
- 用户关闭工作台后，旧消息重放、状态刷新不能将其重新打开。
- 工作台可持续向左扩展；最大化能力需覆盖现有会话 400px 最小宽度的边界。
- 本轮设计可改变工作台内部结构和编辑调用方式，不重写整个宿主框架。

### 2.3 本期不做

多轨视频叠加、复杂转场、关键帧特效、专业调色、多人实时共同编辑、素材物理删除、外部平台发布、任意插件脚本执行不进入首版。

支持同一项目内多素材顺序拼接。不能因 UI 当前从素材进入，就把一条时间线错误限制为单素材。

## 3. 当前实现审计

以下结论来自本地源码阅读；没有把历史对话中的“已完成”描述作为证据。

| 模块 | 当前事实 | 对用户的影响 | 方案 |
|---|---|---|---|
| `ClipActions.tsx`、`WorkbenchPanel.tsx` | 操作生成 `EditIntent`，`onEdit` 只设置前端 pending 状态 | 删除、切开等不落库；没有真正的确认执行闭环 | 连接统一编辑命令服务 |
| `ClipActions.tsx` | 切开按钮使用片段中点 | 用户播放头所在位置和实际切点不一致 | 在播放头切开 |
| `Player.tsx`、`WorkbenchPanel.tsx` | 播放选中原素材；尚无完整成片播放调度 | 排序、删除、倍速后的结果不能正确核对 | 区分原片/成片，增加播放计划 |
| `read.ts` 的 `TimelineClip` | 缺少稳定片段 ID 和每段素材 ID | 多素材与重排后的选择无法可靠跟踪 | 新建规范时间线 DTO |
| `WorkbenchPanel.tsx` | 默认选取 `timelines[0]` | 容易编辑或导出错误版本 | 显式维护当前时间线 |
| `WorkbenchPanel.tsx` | 部分时长/创建按钮依赖响度读取 | 未分析素材也可能不能开始剪辑 | 素材元数据独立提供时长 |
| `OutputList.tsx` | 只有导出结果展示 | 找不到开始导出的入口 | 顶部导出入口、任务状态、下载 |
| `workspace-route.ts` | 有项目、导入、创建原片时间线路由；无完整编辑/导出命令路由 | UI 到业务层缺少写入通道 | 增加受校验的产品 API |
| `runtime.ts` | 有 split/remove/trim/reorder/adjust、render、proposal 等方法 | 有较多可复用能力 | 将规则抽为 UI 与 AI 共用服务 |
| `assertRevision()` | 读取版本后检查，后续多个操作存在异步边界 | 仅有版本字段不能证明并发写安全 | 在事务中原子校验和提交 |
| `refreshTimeline()` | 快照只读 asset/start/end 等字段，并吞掉历史写入异常 | 倍速、静音、名称等不能保证正确撤销 | 完整快照与提交同事务 |
| `render()` | 长任务直接 await 完成；使用实例级阶段状态 | 不能直接当成可靠后台队列；并发隔离需处理 | 持久任务与独立任务上下文 |
| 工作台打开链路 | 当前视频工具与工作台源码未找到 `video_workbench_open` | 模型主动打开尚未接通 | 新增工具、持久事件和去重消费 |
| 旧详情栏 | 部分客户端仍依赖 `sidebarRight` 服务 | 禁用整包会阻塞聊天等插件启动 | 保留兼容服务、拆除展示责任 |
| 构建启动 | 客户端从编译后的 `lib/client.js` 加载 | 改源码重启不等于运行新代码 | 构建、配置同步、运行产物联合验收 |

补充：`reorderSegment` 中存在重复的临时序号移动循环，实施统一写入服务时应审查并以重排测试覆盖；这里记录审查风险，不认定所有重排都会失败。

## 5. 用户流程

### 5.1 AI 生成初剪，用户微调后导出

1. 用户：「把这条旅行视频剪成 60 秒集锦，保留有代表性的景色。」
2. AI 读取当前素材和已有证据，只补齐任务必要的分析。
3. AI 给出结构化初剪方案：预计时长、片段、选择理由、缺失证据。
4. AI 显式打开工作台，显示方案预览；原有时间线保持可查看。
5. 用户点击「采用方案」，生成一次可撤销编辑；若首次创建则生成新时间线。
6. 用户选中第 2 段并删除，界面立即更新并自动保存，无额外确认弹窗。
7. 用户在成片模式播放，看到第 1 段直接衔接原第 3 段。
8. 点击顶部「导出成片」，检查画幅、字幕等设置，点击「开始导出」。
9. 任务完成后提供播放和下载 MP4；工作台可关闭，任务仍继续。

### 5.2 纯手动剪辑

打开工作台 → 新建/选择项目 → 导入视频 → 预览原片 → 创建时间线 → 在播放头切开 → 删除不需要的片段 → 撤销一次检查 → 调整倍速 → 预览成片 → 导出并下载。

此流程不要求模型调用，也不要求先完成语音、响度或画面分析。

### 5.3 纯对话交付

用户明确要求「按刚才确认的方案导出 MP4」时，AI 可以直接创建导出任务并在会话里报告状态与下载入口；不强迫用户使用工作台。

如果用户只是在讨论方案，不能声称已经剪辑或导出。工具真实结果是完成与否的唯一依据。

### 5.4 明确自然语言修改

用户：「把当前时间线第 2 段删除。」

当前时间线明确且版本最新时，AI 可直接执行，并回复「已删除第 2 段，可撤销」。若用户说「这里不太好」或同时存在多条时间线且没有当前上下文，先定位目标，不猜测。

## 6. 交互授权矩阵

| 动作来源/类型 | 默认行为 | 是否需要再次确认 |
|---|---|---|
| 用户点击删除片段、裁短、切开、重排、静音、倍速 | 即时本地反馈，提交并自动保存 | 否 |
| 用户点击撤销、重做 | 直接执行 | 否 |
| 用户明确说出具体编辑命令 | AI 读取最新状态后执行 | 否，除非目标不明确 |
| AI 根据「更精彩/更紧凑」自主挑选片段 | 生成方案预览 | 用户接受一次 |
| 用户接受完整方案 | 作为一个编辑操作提交 | 不逐片段确认 |
| 用户点击开始导出/明确要求导出 | 创建任务 | 不再二次确认 |
| AI 主动建议导出 | 展示建议或设置 | 等用户发起 |
| 删除整个项目或素材索引 | 显示影响范围 | 是 |
| 用历史版本覆盖当前多个编辑 | 显示版本摘要及影响 | 是；普通撤销不弹窗 |

「立即生效」指编辑结果立刻反馈、保存请求自动发出，不等于网络失败时假装已保存。保存状态必须可见。

## 7. 信息架构与布局

### 7.1 工作台对象层次

```text
项目
├── 素材库（原始视频及分析证据）
├── 时间线（一个项目可以有多条，可引用多个素材）
│   ├── 编辑内容与版本
│   └── 导出任务/成片（绑定确定版本）
└── AI 方案（草稿、已采用、已过期）
```

素材和时间线不能互相冒充：从素材进入可展示相关时间线，但项目级时间线才是编辑与导出的主体。返回素材列表不删除编辑，也不更换会话。

### 7.2 三栏外壳

```text
左导航       会话                 工作台
项目/会话    用户目标与 AI 回复    顶栏：项目 / 时间线 | 保存状态 | 导出 | 关闭
                                 原片 / 成片预览
                                 时间线 + 简洁编辑工具栏
                                 素材 / 证据 / 版本 / 导出任务（按需展开）
```

右侧工作台使用根 `rightbar`，只保留一个界面拥有者；不再套遮罩式抽屉。左侧保留手动入口用于找回已关闭工作台。

普通模式：保留会话最小可用宽度，取消额外百分比上限。拉到边界时展示轻量「进入专注编辑」入口；顶栏同时提供可访问的专注按钮。进入专注模式后工作台占主区域，会话折叠为可恢复入口；退出后恢复之前三栏宽度。不让拖拽悄悄把会话压成不可读的零宽列。

现有 400px 会话下限继续用于普通模式；「一直向左拉」的最终产品能力通过明确的专注模式完成，而非声称改一个百分比就能无限扩展。

### 7.3 工作台内部响应式

以容器宽度而非浏览器宽度判断：

- 小于 520px：播放器、时间线优先；素材、证据、版本、任务切换显示；禁止内部三列硬挤。
- 520–899px：播放器 + 时间线，辅助面板按需展开。
- 900px 及以上：允许素材栏 / 预览 / 属性栏并排；时间线横跨整个工作台。
- 顶部导出入口、关闭入口始终可见；工具栏次要操作进入「更多」。

高度不足时保证顶部操作区和当前主操作可达。时间线与辅助区各自管理滚动，不让四五个独立滚动区同时竞争。

### 7.4 编辑工具栏整理

主工具栏只保留撤销、重做、在播放头切开、删除。选中片段后出现对应属性：倍速下拉、静音开关、名称输入；前移/后移、复制等放次级菜单。

证据使用独立「证据」面板和可选择轨道，避免将台词、屏幕文字、停顿、响度等所有按钮与片段操作堆在同一行。字幕预览与导出烧录分别命名。

快捷键收进「快捷键」帮助；保留按钮 tooltip。使用 `Ctrl/⌘+Z` 撤销、`Ctrl/⌘+Shift+Z` 重做，既有复制剪切快捷键只能在编辑区域获得焦点时生效。

## 8. 手动编辑规格

### 8.1 状态与反馈

```text
已保存 → 编辑中（拖动草稿） → 正在保存 → 已保存
                                      ├→ 保存失败：重试 / 放弃本次修改
                                      └→ 版本冲突：读取最新状态，重新决定
```

点击操作可乐观展示；服务端返回规范时间线后替换本地草稿。拖动过程中不逐像素落库，在 pointerup 提交一次，整次拖动只占一个撤销步骤。

第一版采用每条时间线单个在途提交。保存中暂时禁用会产生第二次写入的控件；保留观看、滚动和选择。避免为了“丝滑”引入无法正确重放的客户端写队列。

操作超时不等于未提交：使用相同 operation ID 重试/查询结果，不能重复删除下一段。

### 8.2 操作定义

| 操作 | 语义 |
|---|---|
| 切开 | 在当前成片播放头对应的源位置切开选中片段；不在片段内部则禁用并解释 |
| 删除 | 删除选中片段并自动闭合间隙；不删除源文件 |
| 裁短 | 修改片段源区间，成片时间位置重新计算 |
| 重排 | 修改顺序，保持片段身份与属性 |
| 倍速 | 更新片段速度，同时更新成片时长、播放调度和导出计划 |
| 静音 | 仅静音该片段，预览和导出一致 |
| 改名 | Enter 或按钮提交一次；名称随片段身份保持 |
| 复制/粘贴 | 粘贴产生新的片段 ID，保留来源与设置 |
| 合并 | 同素材、源区间首尾相接、兼容速度与静音；不满足时解释原因 |

### 8.3 空时间线

目标允许删除最后一个片段，变成空时间线，显示「从素材库添加片段」，导出禁用。

当前 schema 和 `refreshTimeline()` 不允许为空；需要迁移旧的区间摘要约束，不能只改前端按钮。迁移完成前保持最后片段删除禁用并明确文案，不能承诺已支持。

### 8.4 撤销、重做与历史

完整快照包含片段身份、顺序、素材、源入出点、速度、静音、名称、时间线输出设置及字幕配置。任何影响编辑结果的属性都不能遗漏。

撤销/重做也产生新的单调递增 revision。维护逻辑编辑历史游标，不用简单 `revision - 1`，否则会在撤销操作之间循环。

单用户场景下，最近一次 AI 已提交编辑也进入同一个历史链，按钮说明操作来源。接受 AI 方案整体算一次操作。新编辑清除可重做分支；恢复历史版本是新的编辑事件。

其他客户端或 AI 在本地读数之后提交了更新时，撤销需版本校验。发现冲突不悄悄覆盖他者的新修改。

旧历史缺失的属性不能推测还原：标记为旧格式记录。升级时保存当前完整基线；完整撤销保证从该基线开始。

## 9. 预览与时间坐标

### 9.1 两种模式

- 原片：查看完整素材，使用源时间；适合找证据、选择区间。
- 成片：按当前时间线顺序播放，使用成片时间；是编辑状态默认核对方式。

切换模式需显示标签。点击源证据可以切换到原片并跳转；返回成片时恢复原位置。不能在播放原片时标注为成片预览。

### 9.2 时间映射规范

内部单位为整数微秒。片段 i 的成片长度：`duration = (source_out - source_in) / speed`，成片起点为之前各段长度之和。

映射：`source_time = source_in + (composition_time - composition_start) * speed`。

区间按 `[start, end)` 处理，边界帧归属明确。倍速除法使用统一舍入策略；累计时间使用未逐段粗略取整的精度计算，在最终媒体边界量化。切开位置按当前素材时基校验；可变帧率素材不假设固定 30fps。

证据属于源素材时间，时间线属于成片时间；同一素材重复出现时，证据可能映射到多个成片区间。两者不能共用一个没有语义标签的 `playheadUs`。

### 9.3 可实现的播放器路径

首版：独立播放调度器消费统一 EditPlan，HTMLVideoElement 执行区间跳转、素材切换、playbackRate 和 muted。跨片段跳转使用预加载；监听媒体真实就绪/seek 事件，不只靠低频 `timeupdate` 裁边。

浏览器预览不能保证所有编码与切点都帧精确、无缝，也不等于 FFmpeg 最终结果。普通剪辑提供可交互近似预览；精确字幕/切点核对提供按 revision 生成的低清预览任务，播放已渲染文件。

后续优化可做双播放器预加载；不把 WebCodecs 全套播放引擎作为首版前提。

字幕叠加须覆盖实际视频可视区域，并以成片时间求 cue。最终字体、描边等以渲染结果为准，界面标注浏览器预览差异。

## 10. 导出与下载

### 10.1 入口及默认设置

顶部固定「导出成片」按钮，不藏在成片列表下方。打开内联导出面板，包含：

- 当前时间线名称、时长、已保存状态。
- 文件名，默认时间线名称加日期；服务端清洗文件名。
- MP4，首版固定经验证可用的编码配置。
- 画幅：保持原样、16:9、9:16、1:1；必要时选择构图焦点。
- 字幕：不烧录 / 烧录已有字幕；默认不烧录。无有效字幕时给出原因。
- 输出路径说明：「完成后下载到浏览器设置的下载位置」。不能假装浏览器能任意写入用户磁盘目录。

暂不展示码率、分辨率等尚未接通的控件。新增这些选项时必须贯穿验证、渲染配置和结果元数据。

用户点击「开始导出」即授权执行。若仍在保存，等待保存成功后再提交；失败时阻止导出并保留设置。已有未保存草稿时不能默默导出旧版本。

### 10.2 任务状态

```text
queued → running → completed
             ├→ failed
             ├→ cancelling → cancelled
             └→ interrupted（服务重启后恢复识别）
```

界面显示阶段（准备素材、编码、上传），有可靠测量再显示百分比；不得虚构进度。首版默认单个重型渲染并发，后续任务排队。

刷新、关闭工作台、断开浏览器不取消任务。取消是独立显式动作，要能停止对应 FFmpeg 子进程并清理本任务临时文件。

重启后：queued 可以恢复；running/cancelling 检查执行者存活，首版标记 interrupted，允许基于原快照重试；不宣称断点续渲染。

### 10.3 快照与结果

创建任务时固定时间线 revision、完整 EditPlan、素材引用、字幕数据和渲染选项。之后用户把 r12 改成 r13，任务仍输出 r12。

完成卡展示名称、时长、文件大小、生成时间、版本、播放、下载、重新导出。若成片版本落后，提示「此成片基于较早编辑，导出当前版本」；旧文件仍可下载。

下载使用授权的同源流式路由及 `Content-Disposition`。不能依赖跨域 OSS 链接的 `download` 属性，也不能把大视频全部读入浏览器 Blob 内存。

任务详情中的原始错误、内部路径、JSON 折叠为诊断信息；默认只显示用户能采取行动的失败原因。

## 11. AI 与工作台联动

### 11.1 当前上下文

上下文至少包含 `session_id/project_id/timeline_id/revision/selected_clip_ids/preview_mode`。保存按会话的编辑上下文，避免全局 localStorage 把其他会话的素材带入当前任务。

UI 状态可以给模型提供定位线索，服务端授权与所有权校验不能依赖客户端自报。模型写入前读取最新时间线。

### 11.2 打开工具

新增 `video_workbench_open`：接受项目、可选时间线/素材、可选方案 ID、目标视图、打开理由。服务端校验对象存在且属于项目，再在工具结果 presentation metadata 中输出结构化指令。

工具语义是「已发出打开指令」，只有客户端确认执行后才能认为界面已打开。无客户端在线时仍保留指令，但模型不得把用户已经看到界面当作事实。

客户端只消费当前会话的新指令。用 session ID + tool call/event ID 去重，记录已消费游标；初始化回放旧日志只重建上下文，不重新弹窗。切换会话时后台结果不抢占当前工作台。

用户关闭只改变可见性；新一次显式打开指令或手动入口可再次打开。刷新后默认保持关闭，除非用户在当前页面显式操作。

### 11.3 提示词替换建议

将当前笼统的「不许替用户改时间线」改为：

> 用户在工作台的直接操作或明确的自然语言编辑指令，可以在目标明确时执行，所有修改保留可撤销历史。你自主选择片段或决定剪辑方案时，应先展示方案和真实依据，用户接受后应用。修改之前读取当前时间线与版本。用户明确要求导出时创建导出任务并报告真实状态。需要用户观看、核对或手动调整时调用工作台打开工具；普通检索和列项目不必打开。

提示词不能替代服务端校验，也不能只更新仓库模板而遗漏实际预设。验收需读取新会话实际使用的提示词与工具列表。

### 11.4 方案接受

方案保存 base revision、来源证据和摘要；接受时检查方案版本及时间线版本。过期方案显示「时间线已修改，请更新方案」，不能覆盖当前手动编辑。已接受方案再次点击返回原操作结果，不重复写入。

## 12. 技术架构

```text
工作台操作 → 产品 API ─┐
                      ├→ TimelineCommandService → SQLite 原子提交
AI video_* 工具 ──────┘                         → 完整历史 / 操作记录
                                                 → 变更通知
读取时间线 → EditPlan → 浏览器成片预览
                   └→ RenderJobService → FFmpeg → OSS / 下载路由
```

### 12.1 统一业务写入

UI 不执行模型工具字符串，不通过聊天消息间接改时间线。新增明确产品 API，调用与 `video_*` 工具相同的业务命令服务。

复用已有剪辑算法，但必须先补齐事务与历史。不能将 HTTP JSON 强转后动态调用 `video[tool]`；动作采用白名单 discriminated union 和运行时 schema 校验。

建议在 `video-workspace/src/` 逐步拆分：

- `timeline-command-service.ts`：编辑、撤销、重做、版本校验、幂等。
- `timeline-repository.ts`：SQLite 事务、完整快照、迁移。
- `edit-plan.ts`：统一的源/成片映射与渲染输入。
- `render-job-service.ts`：持久任务、排队、执行、取消、恢复。
- `workspace-route.ts`：路由、输入校验、错误映射。

不要求首日拆完 `runtime.ts`。按写入、渲染边界抽离；旧方法作为兼容适配入口。

### 12.2 规范编辑请求

示例为拟新增契约：

```json
{
  "operation_id": "客户端生成的 UUID",
  "base_revision": 12,
  "action": { "type": "remove_clip", "clip_id": "clip-b" }
}
```

响应包含 `operation_id`、新 revision、规范 timeline、可撤销/重做状态、可读操作摘要。首次结果写入数据库；同 operation ID + 同请求重试返回相同结果，不再执行；同 ID 不同请求返回冲突。

稳定 `clip_id` 标识片段，ordinal 只表示排序位置。旧 AI 工具暂保留 ordinal 参数，适配器在准确版本下解析成稳定 ID，再调用同一个服务。

### 12.3 数据模型增量

| 数据 | 拟新增/调整内容 |
|---|---|
| 时间线 | 支持空片段集合；revision 覆盖所有影响编辑结果的设置；保留旧摘要字段兼容读取 |
| 片段 | 稳定 clip_id、asset_id、order、source_in/out、speed、muted、name |
| 历史 | schema_version、完整 before/after 快照或可还原引用、操作摘要、来源、时间 |
| 操作记录 | operation_id、请求摘要、timeline_id、结果 revision、响应、执行来源 |
| 导出任务 | 状态、timeline_revision、不可变输入快照、选项、阶段、错误、结果、时间与重试关系 |
| 前端上下文 | 按会话保存项目/时间线/素材选择、宽度、已消费打开指令游标 |

迁移前备份本地数据库。新增字段默认兼容现有记录；旧客户端字段在过渡阶段继续输出。manifest 更新 schema version，同时保留现有读取必需字段。

### 12.4 原子性与同步

预先完成必要的异步读取，再进入短 SQLite 事务；事务内重新读取 revision，校验命令，写片段、revision、完整历史和幂等结果，最后一起提交。事务不能跨网络 await。

外部读取的数据若在提交前可能改变，必须在事务里再校验引用/版本。多个写入者使用同一数据库 CAS/事务语义，不能只依赖浏览器禁用按钮或进程内锁。

manifest/OSS 同步放到提交后任务：本地保存成功与远端同步失败分别呈现。已提交后同步失败不能让 API 报“编辑失败”并引导重复执行。

### 12.5 API 草案

路径以现有 `/goclip-workspace` 为前缀，以下为新增规范：

| 方法及路径 | 用途 |
|---|---|
| GET `/projects/:p/timelines` | 项目级时间线列表 |
| GET `/projects/:p/timelines/:t` | 规范时间线及元数据 |
| POST `/projects/:p/timelines/:t/commands` | 执行白名单编辑命令 |
| GET `/projects/:p/timelines/:t/operations/:op` | 查询超时操作是否已提交 |
| POST `/projects/:p/timelines/:t/undo`、`/redo` | 版本受保护的历史操作 |
| GET `/projects/:p/timelines/:t/history` | 完整可恢复版本摘要 |
| POST `/projects/:p/timelines/:t/exports` | 固定快照并创建任务，返回 202 |
| GET `/projects/:p/exports/:j` | 阶段、结果与版本 |
| POST `/projects/:p/exports/:j/cancel` | 请求取消 |
| GET `/projects/:p/exports/:j/download` | 授权流式下载 |

导出提交需要 operation ID 和 base revision。没有一条 HTTP 连接要等待完整 FFmpeg 渲染结束。

### 12.6 错误与访问控制

错误格式统一为 `code/message/retryable/current_revision` 等结构。400 输入无效，404 对象不存在，409 版本或幂等冲突，422 操作不满足条件，503 执行资源暂不可用。

沿用并核验宿主认证边界；所有新路由验证项目—时间线—素材—任务归属。浏览器写请求核验 Origin/宿主 CSRF 机制，限制 JSON 体积。当前路由文件本身未体现全套授权，实施前必须确认宿主实际中间件覆盖情况。

客户端不能通过 `source: human` 获得额外权限；来源由受信执行入口记录。下载响应支持 Range，不暴露 OSS 凭据。

## 14. 旧详情栏与发布问题的收尾

旧界面不出现，但已有插件对 `sidebarRight` 的依赖不能通过整包禁用解决。最终实现应将服务/注册表与旧视图注册分开；保留兼容层时逐个处理打开文件、终端、计划等调用的去向。

不能仅返回成功但没有任何可见结果。goclip 不提供的旧入口从 UI 移除；仍需保留的内容转会话内卡片或明确的受支持查看入口。旧快捷键和会话右上角展开按钮也必须清理。

构建验收流程必须包含：类型检查 → 有关测试 → 实际客户端/服务端产物构建 → profile 同步 → 重启 → 浏览器核对构建版本与插件清单。

增加开发构建标识或诊断页中的版本号，避免再次通过源码修改推断浏览器已更新。失败信息必须来自实际启动日志和浏览器，而非只检查端口监听。

## 15. 实施阶段与交付门槛

### 阶段 A：领域模型与写入基础

- 新稳定片段 ID、完整快照、操作幂等、事务版本校验。
- UI 与 AI 统一写入服务；旧工具适配。
- 空时间线迁移及安全回读。
- 基础手动操作、撤销重做闭环。

门槛：刷新后修改保持；同版本并发只有一个成功；超时重试不重复执行；速度/静音/名称能完整恢复。

### 阶段 B：真实成片预览

- 显式时间线选择、素材元数据独立读取。
- EditPlan 与原片/成片切换、多素材顺播、变速静音。
- 播放头切开、拖动草稿、证据坐标区分。

门槛：删除、重排、倍速的可见结果与计划一致；无需分析也能剪辑；不再把原片当成成片播放。

### 阶段 C：导出、取消、下载

- 快照导出、持久队列、独立任务上下文、错误恢复。
- 固定导出入口、任务列表、流式下载。
- 明确文件格式、画幅、字幕选项及限制。

门槛：用户从导入到下载完全不依赖 AI；导出期间编辑不会污染输出；页面刷新不丢任务。

### 阶段 D：AI 联动与界面收敛

- 打开工具、事件去重、会话上下文。
- 方案预览、接受与冲突反馈，更新系统提示词。
- 窄栏/宽栏/专注模式、辅助面板与旧详情栏收尾。

门槛：AI 初剪 → 用户微调 → 导出可一次走通；关闭后旧事件不重新打开。

阶段是工程分解，不是四次半成品上线。A–C 是手动剪辑首个可用版本的共同门槛；含用户要求的 AI 联动完整版本需 A–D 全部通过。

不在未验证素材格式、历史迁移和宿主服务边界前承诺精确工期；优先安排 A 的并发/历史与 B 的预览验证，它们决定剩余工作量。

| C06 | AI 方案生成后用户手动改了时间线 | 方案接受报版本过期，不覆盖 |
| C07 | 快速切换素材/时间线 | 旧请求不覆盖新状态 |
| C08 | 越项目访问、无效动作、超大 JSON | 正确拒绝且无数据副作用 |

### 16.3 导出与媒体核对

| 编号 | 场景 | 必须结果 |
|---|---|---|
| E01 | 无待保存编辑，开始导出 | 快速返回任务 ID；后台执行 |
| E02 | 导出 r12 时编辑为 r13 | r12 文件可下载并标记较早版本 |
| E03 | 关闭页面、再打开 | 能找到同一任务及最终结果 |
| E04 | 服务中途重启 | 无永久 running，标识 interrupted 并可重试 |
| E05 | 取消排队/运行任务 | 对应任务停止，其他任务不受影响 |
| E06 | OSS 上传/FFmpeg 失败 | 阶段与可理解原因可见，支持基于原快照重试 |
| E07 | 大文件下载 | 流式响应、可续传，不整体缓存在内存 |
| E08 | 字幕烧录 | 时间映射、选项、成片一致；未选择烧录则不烧录 |

媒体测试夹具至少包括：有声音/无声音、不同帧率和分辨率、重复使用同一源区间、多素材、0.5×/2×、静音片段、边界切点及不支持解码样本。FFmpeg/ffprobe 验证时长、音视频流和选定帧/音频区间，不能只检查返回 HTTP 200。

端到端必须在真实构建产物和浏览器中完成一次「导入 → 编辑 → 撤销 → 预览 → 导出 → 下载播放」。单元测试不等于浏览器布局与媒体验收。

## 17. 性能、可访问性与可观测性

- 点击/拖动本地视觉反馈目标 100ms 内；本地编辑保存 p95 目标 500ms 内，需在明确测试机器和 100 片段样本下测量，属于验收目标而非现状保证。
- 首版基准：30–60 分钟素材、100 片段、数千字幕 cue；列表按需虚拟化，不能每次播放头更新重读整条时间线。
- 导出提交快速返回，编码时间按素材与机器实际显示，不承诺统一完成秒数。
- 键盘能进入工具栏、菜单、时间线和关闭入口；错误使用可读消息；保存/任务状态提供适量 aria-live 通知。
- 字段有显式 label，状态不只靠颜色；焦点离开工作台后不拦截会话输入快捷键。
- 日志关联 operation ID、timeline ID、revision、job ID；不记录凭据或完整视频内容。
- 埋点优先记录闭环成功率、保存失败/冲突、导出失败阶段、下载完成入口使用；单机版可先使用本地结构化日志。

## 18. 关键取舍及风险

1. **保留现有时间线库**：它处理拖拽和轨道展示；持久化、撤销、播放合成、导出由产品业务层负责。更换库不能自动补齐这些能力。
2. **先单个在途写入**：减少错序覆盖风险；未来在稳定片段身份和冲突语义完整后再增加连续操作队列。
3. **本地保存先于 OSS 同步**：缩短编辑反馈，清楚区分本地持久化与远端备份。
4. **异步导出必做**：包装一个长时间 HTTP await 无法满足关闭页面继续执行、恢复与取消。
5. **预览精度分层**：交互预览满足即时编辑；需要精确结果时使用同版本渲染预览。不能宣传浏览器模拟必定逐帧等同最终 MP4。
6. **历史完整性先于“可撤销”承诺**：旧历史缺失字段无法补造；完整恢复从迁移基线开始。
7. **现有宿主兼容性必须验证**：保留服务并不自动保证文件/计划入口仍可用；要逐项明确产品去向。

## 19. 实施完成定义

用户能在同一项目中：让 AI 提出初剪 → 一次采用 → 手动删除或调整倍速并自动保存 → 撤销和重做 → 播放实际编辑顺序 → 点击导出 → 关闭工作台 → 再打开找到完成文件 → 下载播放。

全过程无需阅读工具协议、无需重复确认手动编辑、不会把原片误认为成片、不会把旧版本文件误认为最新版本。所有状态均与持久化数据和任务实际结果一致。
