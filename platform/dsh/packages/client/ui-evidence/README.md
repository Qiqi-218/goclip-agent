# @deepseek-ai/dsh-client-ui-evidence — 证据总览面板

把 `video_evidence_view` 一次调用的结果画成一张**只读**的多轨时间轴卡片。

卡片出现在对话里该次调用的位置（`tool.call.toolview` 的键控席位，键就是工具名），
不新开页面、不加按钮、不改任何数据。

## 它画什么

八条轨道共用**同一条时间轴**，左边缘对齐即同一时刻 —— 这正是这个面板存在的理由：
一条曲线、一个刻度、一句台词落在同一个横坐标上，读起来才是同一件事。

| 轨道 | 画法 |
| --- | --- |
| 响度 | 折线 + 填充，纵轴固定为 −60…0 dBFS；橙色虚线是分析给出的「响」阈值 |
| 镜头 | 一条基线 + 每个切点一根竖线 |
| 停顿 | 按比例定位的色块（最短 3px，否则零点几秒的停顿会细成一根毛刺） |
| 转写 / 屏文字 / 画面 | 按比例定位的色块，悬停显示原文 |
| 章节 | 同上，来自分析结果的分段 |
| 时间线 | 片段色块；**不属于本素材的片段画成空心**，因为它在素材的时间轴上没有位置 |

响度为什么用固定量程而不是素材自己的动态范围：某条素材整个动态范围只有 2.2 dB，
按它自己拉伸会铺满整条轨道、看上去处处都是响的；固定量程下两条素材才能用眼睛比。

## 数据从哪来

面板**不发任何请求**。数据是工具自己投影出去、随会话日志持久化的那份
`presentationMeta.evidence_view`：

```
video_evidence_view 的返回值
  └─ 宿主侧 presentationMeta 投影（只留面板要画的字段）
       └─ tool/result 事件的 data.meta
            └─ 界面卡片读 block.meta
                 └─ evidenceViewModel() 收窄 → SVG 与色块
```

因此重开一次会话日志，面板照原样画出来 —— 没有任何东西依赖这个插件自己的内存状态。

## 组件看不到 ctx

`apply` 只做两件事：注册 `evidence` 命名空间的字典，把组件注册进键控席位。
组件拿到的全是派生的 props（调用阶段、持久化元数据、本地化文案），
它不订阅任何东西，也不请求任何东西。

## 三个刻意的选择

1. **元数据缺失时显示「无数据」而不是空画布。** 载荷里没有 `evidence_view`
   （老日志、或投影失败的调用）时给出明确说明。空画布看上去像「证据全空」，
   那是**另一种**、且不成立的结论。
2. **`missing` 为 `null` 时不显示「六维齐全」。** 投影只保留面板要画的字段，
   所以「说了没缺」和「没说」是两件事，面板不能替它下结论。
3. **`on_this_axis` 直接读宿主的判定，不在界面里重新推导。** 载荷里没有 asset id，
   而「这一段属不属于这条时间轴」只有产出方知道。

## 验收

- `scripts/tools/verify/probe-evidence-view.mjs` —— 26 项断言，覆盖这份载荷的字段名、
  归一化位置与绝对时间的一致性、异轴片段标记、缺项如实上报。
  其中一条断的是**字段名**而不是数值：只比数值时，字段名读错产生的 `null`
  恰好不会触发任何断言。
- `scripts/tools/verify/cdp_panel.py` —— 在真实界面上读渲染结果，并做命中测试
  确认卡片真的被画出来（折叠分组里的元素照样有坐标）。
