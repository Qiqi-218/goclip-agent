# @deepseek-ai/dsh-client-ui-workbench — 剪辑工作台

一面**对话式剪辑的可视化编辑台**：左边列出片段、中间是画面、右边是成片，**下面是一条真正能编辑的时间线**。

它不是对话里的一张卡片，而是**中心区的一个面板**：左侧栏「插件」下面多一个「工作台」按钮，
点它就把中心区换成工作台。

时间线交给 [`@xzdarcy/react-timeline-editor`](https://github.com/xzdarcy/react-timeline-editor)
（MIT），因为一个能用的剪辑时间线需要的交互 —— 拖边界裁剪、吸附、拖动时自动滚、够到帧级的缩放 ——
不是几十行手绘代码能提供的。**数据、坐标换算与「谁写库」仍然全部由本包与宿主负责**：
编辑器只是一个视图，它不持有编辑状态。

## 它画什么

| 区域 | 内容 | 数据 |
| --- | --- | --- |
| 片段 | 每段一条：取自素材哪个区间、多长、是否变速静音 | `…/data/<p>/<a>/timelines` |
| 画面 | `<video>` + 时间读数 | 媒体路由的字节流（支持 Range） |
| 成片 | 每个成片一个播放器 | `…/data/<p>/<a>/renders` |
| 时间线 | 片段铺在**成片轴**上，可拖边界、可缩放 | 同上 |

## 拖动不直接改数据

一次拖动只**产出一条工具调用**（`video_timeline_trim` 加参数），由上层决定是否发出去。
被拖过的片段在界面上画成**虚线**，底部写出「已提出修改：… 等确认后才会生效」。

这样做是因为工具层是唯一的写入者，而它带着 `base_revision` 检查 —— 绕过它直接写会让
「手动编辑、Agent 编辑、多窗口」互相静默覆盖，那正是 revision 机制要防的事。

## 证据轨道：把「为什么剪这一段」画在片子旁边

六个维度都量在**素材**上，而时间线的轴是**成片**。`evidence-model.ts` 负责换算，规矩只有一条：
**被成片取用的部分才画，一个时刻在成片里出现几次就画几次。** 一段素材若被两段取用，它必须在轨道上出现两次；若某段素材根本没被用上，它在成片上没有位置，就不该被塞到端点。

`toFilmSpans` 按片段边界**切开**跨度，而不是整段平移 —— 整段平移会把跨两段的一行字挪到一个错误的位置。

章节与高光来自同一份分析片段，画法却不同：章节要说「这一段讲了什么」，文字必须铺开；高光只说「哪几段值得挑」，位置本身就是答案。只给其中一条，另一个问题就无处可看。

**每个维度在 `availableLanes` 里都要有自己的分支，末尾不留兜底。** 它原来以「有没有高光」收尾，于是任何新轨道都会悄悄按高光的有无来决定 —— 章节就因此永远不出现，而且看起来像是「这条素材没有章节」。

轨道只列出这条素材**真的有**的证据：给一条空轨道会让人以为「这里没有停顿」，而实际是「停顿还没测过」，那是两个不同的结论。

| 轨道 | 画法 |
| --- | --- |
| 台词 / 屏文字 | 按跨度铺文本块，悬停看原文，点一下跳到原片那一刻 |
| 镜头 | 每个切点一根细线（是一个瞬间，不是一段） |
| 停顿 | 半透明色块 |
| 响度 | 按成片宽度分桶，每桶取**峰值**；纵轴按本片实测动态范围 |
| 章节 | 按跨度铺文字块（悬停看摘要，点一下跳到原片那一刻）—— 它回答「这一整片讲了哪几段」 |
| 高光 | 按分析标出的区间上色，悬停看当初写下的理由 —— 它回答「哪几段值得挑出来」 |

**一个反直觉的地方**：证据轨道的动作必须覆盖**成片本身的长度**，而不是「整行」。库把位置换算成像素的公式是 `startLeft + 位置 / scale * scaleWidth`，所以动作的像素宽度是 `end × scaleWidth`。写成 1 会把动作压成一秒宽、所有标记退化成最小宽度；写成一个「很大」的数则会把整行撑到几百万像素、把成片挤成一条线。两种情况看起来都像「轨道是空的」。
## 版本：改坏了怎么回去

每次被接受的编辑都会在改动之前留一份快照（`timeline_history`），所以「回不去」这件事本来就不该发生。这一列列出存在的版本、每一版做了什么、以及回到它的入口。

**回到某一版不直接写库**，和拖动走同一条通道：产出一条 `video_timeline_revert` 调用，带上**你正在看的那一版**。少了这个版本号，一次与别人并发的回滚会静默丢掉对方的工作 —— 一次能覆盖别人成果的撤销，比多一步的撤销更糟。

两点刻意的选择：

- **不显示每一版的片段列表。** 十个版本各自带上整份片段清单，是对「是哪一版」这个问题的过大回答；备注与段数才是人真正用来挑的依据。
- **当前版本画成不可点。** 按下去只会发出一次「回到原地」的编辑 —— 什么也不改，却会推进版本号。

**没有历史**与**读不出来**分开说：前者说明这是一条刚建的时间线，后者说明读取出了问题。合成一句话会把故障说成正常，用户就不会去查。

## 对选中的片段能做什么

动作条给的是：切开、与下一段合并、删除、前移、后移、倍速、静音、起名。

**顺序用两个按钮而不是拖放。** 库提供的行拖拽会把整条轨道搬走，而这里要动的是同一轨道内的一段；用按钮表达既没有歧义，也不必再为「拖到哪个像素算第几位」定一套规则。

**片段名存在片段上**（	imeline_segments.name），不是时间线上。它标的是这一刀里的某一块——同一段素材在别处再用一次是另一块。因此起名**会推进 revision**（与时间线改名不同）：把一段叫作「开场」改变了这一刀读起来的样子。界面只在真的有名字时才显示它，序号是位置、名字是「这一段是什么」。

点时间线上的一个片段会**同时**选中它并把画面跳到那一秒，动作条随之出现：切开、与下一段合并、删除、倍速、静音。

**按钮只在该动作真能成功时才可用，并给出理由。** 宿主对合并有三条拒绝条件（同一素材、播放设置相同、在素材上首尾相接），`canMergeWithNext` 镜像了其中能查的两条；不满足时按钮灰掉、标题写明缺什么。一个存在但必然失败的按钮会教错「合并」是什么意思。

**点一下同时做两件事**是刻意的：选中让动作条出现，跳转让眼睛落到那一段上。拆成两次点击会让最常用的动作变成两下，而这两件事本来不冲突。

**每个按钮都只产出工具调用**，与拖动同一条通道 —— 工具层是唯一写入者，带着 `base_revision` 检查。直接写会更快，也会让版本机制变成装饰。

**切开按钮切在片段正中**：按下按钮时没有「指针在哪」这回事，而中点在任何片段上都存在。想切别的位置用时间线上的拖动。

## 成片列里也有失败的那些

这一列列出这条素材上**每一次**渲染尝试，包括失败的。

失败的任务原先被过滤掉，理由是「没有产物就没有可播的东西」。那对播放器成立，对人不成立：一次烧录中崩掉的渲染正是需要看见的东西，而列表漏掉它会把「渲染过三次」报成「没有成片」。失败的条目给出**死在哪一步**，并把走过的每一步折在下面 —— 「哪一步」是这一栏唯一能据以行动的信息，下载失败与烧录失败要做的事完全不同。

宿主侧相应地改了三处：

- **阶段记录连成败一起记。** 原来只记耗时，于是「管线走到一半停了」这个现象无法区分「最后一步失败了」与「还没走到下一步」。
- **失败时把已走过的阶段一并存进 `jobs.detail`**（JSON：error + failed_stage + stages），而不是只存 error 字符串。
- **`detail` 是历史列。** 它可能是这个格式之前写下的纯文本，所以读取时先试 JSON、失败则退回成一条备注 —— 当作 JSON 读会丢掉所有旧成片的备注。

## 它看哪条素材

面板注册在 `main` 槽的键控席位上，**宿主的 owner props 是空的**，而且这个槽是 root 作用域 ——
它既没有 props 可拿，也读不到会话的工具结果。所以素材来自**地址片段**：

```
http://127.0.0.1:8098/?token=…#project=<项目>&asset=<素材>
```

**用片段（`#`）而不是查询串（`?`）不是风格选择**：实测 token 登录回 `303 See Other` +
`location: ./`，**整个查询串在浏览器拿到页面之前就被丢掉了**，带 `?project=…` 的链接到达时
是一个裸 `/`，工作台空着。片段从不发给服务器，任何重定向都碰不到它。查询串仍作为后备读取。

## 数据从哪来

宿主侧 `video-workspace` 注册一条只读路由，三个维度都走它：

```
GET <前缀>/<项目>/<素材>                       → 素材字节（Range → 206）
GET <前缀>/<项目>/<素材>/render/<任务>         → 成片字节
GET <前缀>/data/<项目>/<素材>/<维度>           → 测量结果的 JSON
```

维度是路径**最后一段**，所以一条路由回答所有维度，而不是一个维度一条路由。
未测量回 404、素材不存在也回 404、读取失败回 502 —— 三种结局必须能分辨，
否则界面会把「还没算」和「算不出来」显示成同一句话。

**播放地址一律指向这条路由，不把 OSS 签名地址发进页面**：签名地址会带上 AccessKeyId，
而且签在一段时间后就过期；路由每次请求重新签，并按 Range 转发。

## 组件看不到 ctx

`apply` 只做三件事：注册 `workbench` 命名空间的字典、把面板注册进 `main` 的键控席位、
把按钮注册进 `sidebar.panellist`。组件拿到的全是派生的 props，不订阅、不请求之外的任何东西。

**侧栏项的 `id` 就是中心面板 id**：`ui-sidebar` 自己把它当 `MainPanelId` 用，
`ui-layout` 订阅 `main` 槽发现新键并允许选中它。所以「点侧栏 → 中心换成工作台」
不需要写切换逻辑，注册一个 id 同时完成两件事。

## 为什么对话没有搬进右边栏

设想的布局是「工作台在中间、对话在右边栏」。**用公开接口做不成**，两条依据都查过：

1. **中心面板会释放右侧栏的会话绑定。** `ui-sidebar-right` 把在屏会话算成
   `activePanelId === null ? selected.sessionId : undefined` —— 选中任何中心面板
   （包括这个）都会主动丢掉那个绑定。右侧栏不是对话的第二份副本，而是
   「中心正在看的那个会话」的视图。
2. **右侧栏的 tab 自己绑不了会话。** 承载对话需要 `SessionProvider`，
   而 `PropsRenderSlots` 只在这个条目**声明了 session 作用域子槽**时才给这个座位；
   `sidebar.right.pane.tab` 一个子槽都没声明，它的 props 带 `SessionStandardProps`。
   写出来试会被编译器直接拒绝。唯一在那个位置承载对话的包（`ui-subagent`）
   走的是 `sidebar.chat.conversation` —— 一个它为子会话 tab **自己声明**的槽，
   而一个槽键只能有一个属主。

并排放需要改上游：要么让 `main` 接受 session 作用域的键，要么让 `ui-sidebar-right`
在选中中心面板时保留绑定。两条都不属于这个包能改的范围。

## 字幕预览：调完样式不必先导一次

开关在证据轨道那一行的末端，默认关着 —— 它覆盖在画面上，而画面的主要用途是看素材；开着它是一次明确的选择，不是一个默认状态。

**它画在画面上而不是另开一条横条**，因为字幕的位置就是要选的东西之一：「底部居中」和「左上角」是不同的决定，画在别处会让两者看起来一样。

**显示哪一句由成片坐标决定**，与导出、烧录用的是同一条换算路径。三处各写一份换算就会各错各的，而错的位置只有在有人看片时才发现。同一段素材被用了两次时，预览也画两次 —— 成片里真的有两处。边界上两句都够格时取后一句：正在画的那一帧是新句的第一帧，多留一帧旧句读起来像字幕比说话慢半拍。

**这是近似，不是烧录，差别写在开关的悬停说明里而不是藏着。** 浏览器画不出 ffmpeg 会产出的同一批像素：字体由浏览器解析（libass 用的是它自己的），未知字体族的替换方式不同，烧录的边距是按输出画面的真实尺寸算的。它忠实呈现的是人在挑的那几件事 —— 颜色、粗细、描边、底框、以及文字落在画面的哪里。

**样式随 `timelines` 一起返回**，而不是让界面为它再读一次：两个地址就是两个到达时刻，「改了样式但预览还是旧的」于是成为可能。


## 分界线可以拖，里面的东西跟着重新适配

四条分界：左栏右缘、右栏左缘、预览与时间线之间，以及时间线自身的上下边（最后一条由前一条的拖动决定高度）。双击任一条恢复默认；分界线可聚焦，方向键一次移 10px、按住 Shift 移 40px —— 一条只能拖的分界线对键盘用户等于不存在。

**尺寸放在注册声明的 store 里，不在组件 state 里。** 面板切走时会卸载，组件内的 state 会跟着消失，而「我把片段栏拉宽过」是一次调整、不该每次回来都重来一遍。

**尺寸是像素，不是比例。** 比例会让同一个布局在窄窗口里悄悄把某一栏重新分配 —— 人明确调过的宽度应当保持不变，只有中间那一栏去吸收窗口的变化。

**指针位置解成尺寸，而不是累加位移。** 累加会让夹取吞掉超出边界的位移，于是拖过界再拖回来会停在离手差一截的地方；按位置解就会精确地跟回来。这一处的换算抽成了 `resolveDivision` / `resolveLowerHeight` 两个纯函数，因为「从哪条边量」写错会让分界线往反方向走，而只问「数字变了没有」的测试抓不到。

**时间线那一条按位移解，另外两条按位置解。** 两条竖直分界线的缝是舞台自己的边，可以直接解；横向那条的缝是时间线的**上缘**，而时间线的下缘不是舞台的任何一条边 —— 按位移解就不需要布局。

**中间一栏有下限**（260px）：画面被挤没了，两条竖直的分界线还能拖，但屏幕上什么都不会变。


## 时间线的轴是原片，不是成片

刻度、片段、播放头、点击定位全都用**同一个时间基**：这条素材自己的秒数（0 → 43:04）。片段画在它真实的素材位置上，**片段之间露出没被用到的空隙** —— 那些空隙就是这一刀丢掉了什么，在首尾相接的成片轴上完全看不见。

**早先这条轴是成片时间**，于是屏幕上同时存在两个时间基：点轴的 40 秒，画面跳到素材的 40 秒，而那一秒根本不在成片里。这个错不是「换算写错了」，是**设计里有两个时间基**；去掉一个之后这一类错没有存在的地方。

带来的简化是连带的：

- **点击定位不需要换算** —— 轴上的秒数就是素材秒数。
- **边界拖动的位移不需要乘倍率** —— 拖 1 秒就是 1 秒素材。在成片轴上 2 倍速的一段要乘 2，而漏掉那个因子只会让取用区间短一半：画面还在，只是少了一截，要看片才发现。
- **证据标记不需要重新定位** —— 一个标记画在它被测量到的那一刻。
- **响度曲线覆盖整条素材**，不再只画被取用的部分：曲线是素材的属性，裁到这一刀会让两刀不同的剪辑看起来音频不一样。它也因此不再需要片段作为输入。

**成片时长仍然显示**，在标题栏与轴并排（「原片 2584.1 秒 · 成片 86.2 秒」）：两个数回答不同的问题 —— 轴是素材多长，读数是被倍速折算后这一刀有多长。只给一个数会让人以为轴就是成片，那正是先前那个错。

**导出与字幕烧录仍然按成片时间走**：`filmPositionOf` 与 `toUsedSpans` 就是为此保留的，它们只是不再决定时间线画在哪里。

缩放的默认值随轴一起改了：轴从 86 秒变成 2584 秒，30px/秒会让它宽 77,000 像素，所以默认是 4px/秒（整条 43 分钟约 10,000 像素），范围 0.5–400px/秒。


## 沿时间轴移动：滑轴与缩放

库把自己的滚动条藏了起来，而这条轴在默认缩放下有近万像素宽 —— **屏幕上没有任何东西说明右边还有内容、或者还有多少**。滚轮能移动它，但滚轮既不可发现、也抓不住。所以底部画了一条滑轴：**地图 + 轨道 + 滑块**。

- **上半条地图**是整条录制的缩略：亮块是被取用的区段，空隙是没被用到的秒数。它是用来瞄准的，不是用来编辑的 —— 详细到能编辑就会变成第二条时间线。
- **滑块宽度就是「现在看得到多少」**（视口 ÷ 内容）。这个比例本身就是信息。
- 点轨道往那里去并**居中**；滑块可拖；方向键移四分之一屏、Shift 移近一整屏、Home/End 到两端。只能拖的滑轴对键盘用户等于不存在。

**Ctrl/⌘ + 滚轮缩放，锚在指针上。** 锚定是这件事的全部：以视口左缘为锚，会让「想看清楚」的动作恰好把要看的那一刻推出屏幕。换算轴上的位置是 `(scrollLeft + anchor) × next / current − anchor`；按「滚动量乘缩放比」会漂，因为锚点不在滚动原点上。

**测量时机是这一处真正的坑**，三条都在真浏览器里量过：

1. **滚动量读 DOM，不走库的回调。** 直接读 `.timeline-editor-edit-area .ReactVirtualized__Grid` —— 库里有**两个** `.ReactVirtualized__Grid`（时间区一个、编辑区一个），时间区那个不滚动；选错会让锚定漂 25 秒。
2. **内容变宽不会触发 `ResizeObserver`。** 首次挂载时 grid 存在但**还是空的**，`scrollWidth === clientWidth`，看上去「没有可滑的余量」；而元素自身的框没变，观察器不会为此触发。所以在**行数变化**时重量一次。
3. **构建失败会让上面两条都白做。** 排查期间客户端 bundle 有一次构建中止，服务于是继续给旧产物 —— 屏幕上的表现和「代码没写对」一模一样，只有比对产物内容才分得出来。

## Model Experience

None, as this package only draws measurements the host has already computed and contributes no tool, prompt text, or model-visible field.

#### KV Cache effect

Does not invalidate; the panel issues no model request, so opening or interacting with it leaves the request prefix exactly as the agent loop built it.

## Known Limitations and Deferred Work

- **拖动只提出修改，不提交。** 一次拖动产出一条 `video_timeline_trim` 调用并把它显示出来；
  真正发出去仍要经过对话。工具层是唯一写入者，而它带着 `base_revision` 检查。
  让界面直接写会绕过那道检查，也就会让手动编辑、Agent 编辑与多窗口互相静默覆盖。
- **一次只编辑一条时间线。** 多条时间线只取第一条：所有时间线的片段序号都从 0 开始，
  摊平后序号相撞，而编辑是按序号定位的 —— 那会改到另一条片子上。
- **引擎自带的运行器没有接。** 时间线由我们的播放器驱动（`setTime`），
  所以它自带的播放/暂停与 `effectId` 回调链没有使用；接上它意味着两套播放状态。
- **缩略图与音频波形轨道未做。** 这个库不提供，要自己接。
- **素材选择靠地址。** 工作台与「当前对话」之间没有自动联动，因为那条路径被
  `main` 槽的作用域挡住了（见上文）。目前用链接指名素材。
